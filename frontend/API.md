# API, которого ждёт интерфейс

Все запросы идут на тот же домен, базовый путь задаёт `API_BASE` при сборке (по умолчанию `/support/api`). Тело и ответ в JSON, время в ISO 8601 с часовым поясом. Ключей во фронте нет: модель, почту и Webim вызывает сервер.

Обязательная часть для проверки цепочки на стенде: разделы «Чат» и «Решения менеджера». Остальное интерфейс берёт, если сервер это отдаёт; если нет, вкладка показывает пример данных и пишет об этом строкой сверху.

Форма сообщений чата повторяет то, что умеет бот Webim («Умный бот 2.0»): текст, кнопки-ответы, файл по ссылке, перевод на менеджера и закрытие чата. На пилоте меняется только адаптер на сервере, интерфейс тот же.

## Чат на сайте

### `POST /chat/sessions`
Клиент открыл чат. Сервер создаёт разговор и возвращает приветствие.
```json
// запрос
{ "page": "https://analyzebot.ru/support/" }
// ответ
{ "session_id": "s_123", "messages": [Message] }
```

### `POST /chat/sessions/{session_id}/messages`
Клиент написал текст или нажал кнопку-ответ. Сервер отвечает тем, что агент сказал сразу.
```json
{ "text": "Продлить Касперский на 40 узлов" }
{ "text": "Выставить счёт", "button_id": "invoice" }
```
Ответ: `{ "messages": [Message] }`.

### `GET /chat/sessions/{session_id}/messages?after={seq}`
Интерфейс спрашивает раз в 3 секунды, пока чат открыт. Сюда приходит всё, что появилось позже: ответ менеджера через агента, письмо отправлено, закрытие чата. С `after=0` возвращается вся переписка (так чат восстанавливается после перезагрузки страницы).

### `POST /chat/sessions/{session_id}/rating`
```json
{ "stars": 2 }
```
Оценка 3 и ниже попадает менеджеру в «На проверку».

### Message
```json
{
  "seq": 7,
  "from": "agent",              // agent | manager | system | client
  "type": "text",               // text | file | close
  "text": "Счёт выставил, отправить на почту?",
  "buttons": [ { "id": "mail", "text": "Отправить на почту" } ],
  "file": { "name": "Счёт № 2411-0457.pdf", "url": "/support/api/files/inv-2411-0457.pdf", "size_kb": 46 },
  "author": "Антон",            // для from=manager
  "time": "2026-11-26T11:25:00+03:00"
}
```
`seq` растёт внутри разговора, интерфейс не показывает одно сообщение дважды. `system` выводится серой строкой по центру («Менеджер Антон подключился»). `close` закрывает разговор и показывает оценку.

## Решения менеджера (кабинет, вкладка «Сегодня»)

### `GET /cases`
Случаи, где агент ждёт менеджера, плюс решённые за сегодня.
```json
{ "cases": [Case], "review": [ReviewItem], "today": { "closed": 24, "total": 27, "spent_rub": 12 } }
```

### Case
```json
{
  "id": "c_1",
  "kind": "approve",            // approve: согласовать или отказать; answer: агент не знает ответа
  "status": "waiting",          // waiting | approved | refused | answered
  "deadline": "2026-11-26T11:38:00+03:00",
  "title": "ООО «Северная линия»: отсрочка 30 дней",
  "amount_rub": 92880,
  "desc": "Ольга, сисадмин · клиент с декабря 2025 · счёт № 2411-0457 · продление Kaspersky на 40 узлов",
  "advice": "Можно согласовать: отсрочки в договоре нет, но прошлый заказ № 1512-0388 оплачен за 2 дня, долгов нет",
  "recommend": "approve",       // approve | refuse
  "effect": "Сразу отправит Ольге ключ продления и счёт с оплатой до 24 декабря",
  "approve_label": "Согласовать 30 дней",
  "refuse_reasons": ["По условиям магазина скидки нет", "Скидка возможна только по договору"],
  "refuse_reply": "Скидку на 60 мест КриптоПро согласовать не можем: …",
  "rule": { "text": ["Отсрочка до", "{days}", "дней, если прошлый заказ оплачен вовремя и счёт до", "{limit}", "₽"], "params": { "days": 30, "limit": 100000 } },
  "decided_at": null,
  "decided_by": null,
  "result": null                // после решения: что агент сделал, одной фразой
}
```

### `POST /cases/{id}/decision`
```json
{ "action": "approve" }
{ "action": "refuse", "reason": "По условиям магазина скидки нет", "reply_text": "…" }
{ "action": "answer", "reply_text": "Да, КриптоПро CSP 5.0 работает на macOS.", "add_to_help": true }
```
Ответ: обновлённый `Case`. Сервер передаёт решение агенту, агент пишет клиенту в чат и, если нужно, отправляет письмо.

### `GET /cases/{id}/events`
Как шёл разговор, для раскрывашки в карточке и для журнала.
```json
{ "events": [ { "actor": "client", "name": "Ольга", "time": "…", "text": "…" },
              { "actor": "agent", "time": "…", "text": "…", "source": "Справка «Продление»" },
              { "actor": "manager", "name": "Вы", "time": "…", "text": "Согласовали отсрочку 30 дней" } ] }
```

### `POST /rules`
Менеджер сделал решение правилом. Ответ: новое правило `{ id, title, meta }`.
```json
{ "case_id": "c_1", "params": { "days": 30, "limit": 100000 } }
```

## Журнал

`GET /journal` → `{ "items": [JournalItem] }` за последние дни. Фильтры «Не закрыты», «Проверить», период, канал и поиск кабинет считает сам по полям `open`, `review`, `time` (или время в конце `meta`), `channel`, `client`, `inn`.

`GET /journal/{id}` → `JournalItem` с полями `events`, `files`, `cost_rub`, `manager_min`, `next`, `sent`.

`POST /journal/{id}/review` → `{ "ok": true }` (агент ответил верно) или `{ "fix": "Клиент уже назвал срок лицензии…" }`.

## Знания, агент

`GET /knowledge`, `GET /agent/stats`, `GET /agent/settings`, `PUT /agent/settings`, `POST /agent/pause` с `{ "paused": true }`. Формы ответов в `src/cabinet/demo-data.js`: интерфейс ждёт от сервера те же поля.

`GET /agent/status` → `{ "state": "on" }`, где `state`: `on`, `paused`, `limit` (лимит потрачен), `down` (модель не отвечает); с `since` и `text` для строки-предупреждения.

`POST /rules/{id}` с `{ "enabled": false }` выключает правило, `true` включает.

Знания:
- `POST /knowledge/pending/{id}/add`: ответ менеджера из «Ждут добавления» становится статьёй справки.
- `POST /knowledge/articles` с `{ "title", "text" }`: новая статья (кнопка «Дописать справку»).
- `PUT /knowledge/articles/{id}` с `{ "text" }`: правка статьи.
- `DELETE /knowledge/fixes/{id}`: убрать поправку из проверок.

`PUT /agent/settings` принимает только изменённые поля, например `{ "limit_rub": 1200 }`, `{ "model": "alice-flash" }` или весь список `functions`, и возвращает настройки целиком.

## Что обязательно для стенда

Чат (`/chat/...`) и решения менеджера (`/cases...`). Это и есть цепочка: клиент пишет, агент отвечает, сложное уходит менеджеру, ответ менеджера возвращается в чат. Остальные разделы кабинета без сервера показывают пример с макета и пишут об этом строкой сверху, так что их можно подключать постепенно.

Локальная заглушка всех адресов: `scripts/mock-api.mjs` (запускается через `npm start`). Она отвечает по ключевым словам и нужна только для проверки интерфейса.
