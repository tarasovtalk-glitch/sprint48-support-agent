# Интерфейс агента поддержки Softline Store

Три страницы для стенда `https://analyzebot.ru/support/`:

| Адрес | Что это |
|---|---|
| `/support/` | Экран чата: окно в виде Webim с ИИ-помощником открыто сразу. На широком экране слева короткое пояснение и ссылка в кабинет, на телефоне окно во весь экран |
| `/support/cabinet/` | Кабинет менеджера: «Сегодня» (решения), «Журнал», «Знания», «Агент» (статистика, лимит, настройки) |
| `/support/site/` | Копия главной страницы магазина с тем же живым чатом, свёрнутым в кнопку справа внизу: так демо начинается глазами посетителя сайта. На главный экран стенда ведёт кнопка «Глазами клиента» |

Без фреймворков и зависимостей: HTML, CSS и JS, сборка около 0,6 МБ и ещё 4,9 МБ копия страницы магазина в `site/`. Все пути относительные, поэтому страницы работают под `/support/` без настройки.

Если клиент открывает чат с карточки товара, адрес карточки передаётся параметром: `/support/?page=https://store.softline.ru/kaspersky/kl4141rcefr-248971/`. Чат отправляет его серверу в `page_url`, и на фразу о покупке агент берёт позицию из этой карточки. Принимаются только адреса `https://store.softline.ru/` до 600 знаков.

## Сборка

```bash
cd frontend
npm ci
npm run build
```

Результат в `frontend/dist/`. Эту папку целиком отдаём по адресу `/support/` (пример для Caddy ниже, в разделе «Ключи»).

Переменные сборки:
- `API_BASE`: адрес API агента, по умолчанию `/support/api`.
- `DEMO=1`: всё работает на примере данных, без сервера.

Сборка пишет их в `dist/config.js`. Этот файл можно поправить прямо на сервере, без пересборки.

## API

Контракт в корневом [README](../README.md), раздел «API для фронтенда». Экраны чата и кабинета не знают адресов сервера: их запросы переводит `src/api.js`.

| Что на экране | Запрос к серверу |
|---|---|
| Клиент открыл чат | `POST /sessions`, токен разговора хранится во вкладке |
| Перезагрузил страницу | `GET /case/messages`: вся беседа с сервера, кнопки живы только у последней реплики агента |
| Клиент написал или нажал кнопку-ответ | `POST /case/messages`: текст уходит как `{text}`, кнопка как `{action, value}`, плюс `page_url` карточки, если чат открыт с `?page=`. Кнопки берутся из `buttons` реплики агента |
| Ответ менеджера и PDF КП в чате | `GET /case/messages?after=<последний id>` раз в 3 секунды. `document_url` из реплики менеджера, ссылка живёт 15 минут |
| Кабинет, «Сегодня» | `GET /manager/cases`. Слева очередь по сроку (срок = последняя реплика + 2 минуты, просроченные сверху), в середине карточка: заголовок, первая реплика клиента, шаги агента, что произойдёт после ответа. Проверка КП (`reason: quote_review`) показывает КП с позицией, суммой и реквизитами и кнопку «Отправить КП в чат», остальные причины поле ответа и «Ответить клиенту» |
| «Отправить КП в чат», «Ответить клиенту» | `POST /manager/cases/{id}/decision`: `approve`, `version`, `request_id`, текст менеджера в `reply` (необязателен). Повтор после обрыва идёт с тем же `request_id`. На 409 кабинет просит обновить страницу |
| «Что сделал агент» и «Разговор в чате» | `GET /manager/cases/{id}/journal`: шаги со временем из `events` (поиск, реестр, расчёт, купон, передача менеджеру, решение), реплики из `messages`, в журнале ещё «Во что обошёлся» из `usage`. Если журнала на сервере нет, только переписка из `/messages` |
| «Журнал» | `GET /manager/cases?state=all&limit=100&offset=0`: разговоры дня по часам (текущий час открыт, прошлые свёрнуты, ночь одной группой), выбор дня и календарь, поиск по клиенту и ИНН. Ждущие решения ведут в «Сегодня», закрытые открываются карточкой с КП и перепиской |

Чего в API пока нет, кабинет показывает на примере данных и пишет об этом строкой сверху: правка скидки в КП, чат менеджера с клиентом и «Вернуть агенту», пауза и лимит агента, вкладки «Знания» и «Агент», проверка разговоров из журнала. С живым API кнопки этих действий скрыты, а не ведут в никуда.

### Ключи

В исходниках и в сборке ключей нет.
- `X-Demo-Key` подставляет веб-сервер и только в `POST /sessions`: по нему чат получает токен разговора, дальше ходит с токеном. Общего ключа на весь `/support/api/` нет. На стенде это Caddy:
  ```caddy
  handle /support/api/sessions {
      reverse_proxy 127.0.0.1:8000 {
          header_up X-Demo-Key {env.SUPPORT_DEMO_KEY}
      }
  }
  handle /support/api/* {
      reverse_proxy 127.0.0.1:8000 {
          header_up -X-Demo-Key
      }
  }
  handle /support/* {
      uri strip_prefix /support
      root * /srv/support/frontend/dist
      file_server
  }
  ```
  Путь к `dist` на стенде свой. Ключ, присланный из браузера, Caddy заменяет или убирает.
- Ключ менеджера кабинет спрашивает один раз полем и держит до закрытия вкладки (`sessionStorage`).

## Локальная проверка

```bash
# сервер агента из корня репозитория
SUPPORT_DATABASE=./local.sqlite3 SUPPORT_DEMO_KEY=… SUPPORT_MANAGER_KEY=… uvicorn support_app.app:deployment_app --factory --port 8000
# интерфейс
cd frontend
SUPPORT_DEMO_KEY=… npm start      # http://localhost:8080/support/ и /support/cabinet/
npm run preview                    # то же из dist
node scripts/serve.mjs --no-api    # без сервера: как интерфейс выглядит, если API не отвечает
```

`scripts/serve.mjs` отдаёт страницы и передаёт `/support/api` на сервер агента (`SUPPORT_API`, по умолчанию `http://127.0.0.1:8000`), подставляя `X-Demo-Key` в `POST /sessions` так же, как Caddy на стенде.

Режимы без сервера: `/support/?demo` (сценарий чата без сервера), `/support/#offhours`, `/support/#now` (чат как сейчас, меню и менеджер), `/support/cabinet/?demo` (кабинет на примере, часы истории 10:08). Состояния кабинета с макета: `?demo&limit` (лимит потрачен, агент молчит), `?demo&paused` (агент на паузе), `?demo&empty` (очередь пуста).
