# SMF — ИИ-агент поддержки Softline Store

Конкурсная задача №6 хакатона «ИИКузница». Агент помогает клиентам магазина подобрать лицензии, отвечает на вопросы о заказах и счетах, готовит КП и передаёт сложные обращения оператору со сводкой.

Веб-чат Softline работает на Webim. Адаптер API «Умный бот 2.0» есть в коде (`support_app/webim.py`) и проверен на эмуляторе Webim; на живом аккаунте Webim не проверялся. Конкурсное демо использует отдельный стенд и данные, разрешённые организаторами для демонстрации.

Веб-демо — [analyzebot.ru/support/](https://analyzebot.ru/support/). Проект использует индекс официального каталога Softline, выданного организаторами. Исходная выгрузка каталога и обезличенные примеры обращений хранятся отдельно от кода.

## Запуск сервера

Конкурсный стенд работает в режиме чата (`SUPPORT_CHAT_ONLY=1`). Цена и дата для КП берутся из индекса каталога. Менеджер проверяет черновик, после одобрения PDF появляется в том же диалоге. По запросу счёта после ввода реквизитов агент прикладывает демонстрационный расчёт. Для позиции с ценой и флагом отсутствия агент указывает, что поставку подтвердит менеджер.

Python 3.10+, зависимости в `requirements.txt` и шрифт DejaVu Sans или Arial для PDF. Запуск локально через `uvicorn support_app.app:deployment_app --factory --host 127.0.0.1 --port 8767`. Для контейнера используется `Dockerfile`. Папка SQLite должна быть доступна на запись процессу, в контейнере это пользователь `10001`.

`SUPPORT_DATABASE` задаёт путь к SQLite, `SUPPORT_SCENARIO_PATH` — путь к JSON одного сценария с той же структурой, что и `support_app/demo.json`. `SUPPORT_DEMO_KEY` и `SUPPORT_MANAGER_KEY` — отдельные закрытые ключи для тестового стенда, каждый длиной не менее 24 символов. `YANDEX_API_KEY` и `YANDEX_MODEL_URI` включают модель: определение намерения и многошаговый ход агента (раздел «Как агент решает задачу»). Действия-кнопки работают и без модели. `SUPPORT_DAILY_BUDGET_RUB` и `SUPPORT_TOTAL_BUDGET_RUB` задают бюджет модели на стенде. `SUPPORT_SMTP_HOST` включает доставку в тестовый Mailpit, порт задаётся `SUPPORT_SMTP_PORT` (1025 по умолчанию). Для повторной доставки включаем в Mailpit `MP_IGNORE_DUPLICATE_IDS`.

## API для фронтенда

Все пути начинаются с `/support/api`. Клиентский токен и ключ менеджера передаём заголовками. В исходники и в сборку фронта их не встраиваем.

Основной режим стенда — `SUPPORT_CHAT_ONLY=1` (по умолчанию). Он принимает только веб-чат, пишет историю и не ставит почтовые задания. Сценарий прежней SMTP-проверки доступен при явном `SUPPORT_CHAT_ONLY=0` и отдельном сценарии. Коммерческое предложение в чате появляется только после решения менеджера. В фиде у позиции КриптоПро `410137` нет артикула, поэтому используется явно подписанный ID предложения. НДС не выдумывается.

Сценарии с известным артикулом обрабатываются по каталогу. При подборе по задаче модель выбирает инструменты уточнения, поиска, проверки реестра и подготовки черновика. Состояние клиента и допустимость действий проверяет сервер. В журнале видны вызовы модели, исполненные инструменты, поиск, проверка реестра, расчёт и передача менеджеру. В модель отправляются только безопасные признаки шага и разрешённые слова. Исходная переписка, название клиента и реквизиты остаются в базе стенда.

| Метод и путь | Вход и результат |
| --- | --- |

| `GET /case` | `Authorization: Bearer <session_token>`. Текущий `state`, `version`, `offer`, `payment_due` и заметка менеджера. |
| `POST /case/messages` | Авторизация клиента. JSON с `text` или серверным `action` и `value` нажатой кнопки. Можно передать `page_url` исходной карточки товара Softline. Ответ `reply`, `intent`, `document_url`, `case`, `messages` и `buttons [{label,action,value}]`. Для веб-чата `channel` отсутствует или равен `chat`. |
| `GET /case/messages` | Авторизация клиента. Восстановление беседы или чтение новых реплик через `?after=<id>`. Ответ `messages [{id,role,text,document_url,buttons,created}]`. |
| `GET /documents/{access_id}` | PDF. Ссылка действует 15 минут, старый счёт перестаёт открываться при смене состояния. |
| `GET /manager/cases` | `X-Manager-Key`. По умолчанию очередь ожидающих. Журнал всех разговоров — `?state=all&limit=50&offset=0`. Каждая строка включает `created`, `updated` в UTC и `first_client_message`, а для КП также `reason` и `quote` с названием компании, ИНН и КПП. |
| `GET /manager/cases/{id}/messages` | Авторизация менеджера. Переписка обращения с временем каждой реплики. |
| `POST /manager/cases/{id}/decision` | Авторизация менеджера. `choice` (`approve` или `reject`), текущая `version`, UUID `request_id` и необязательный `reply` для клиента. `note` поддерживается как прежнее имя. Повтор той же команды возвращает её результат. Устаревшая версия даёт `409`. При подтверждении КП `document_url` также появляется в истории клиента. |
| `POST /manager/cases/{id}/rule` | Авторизация менеджера, `confirmed: true`. После ручного согласования создаёт правило по этому клиенту и договору. |
| `GET /manager/cases/{id}/journal` | Авторизация менеджера. События и токены модели для калькулятора. |
| `GET /manager/knowledge` | Авторизация менеджера. Сохранённые правила с основанием и источником. |
| `POST /catalog/selection` | `X-Demo-Key`. JSON `mode` (`known` или `needs`), `query`, `product` для известного продукта и уточнения `users`, `term_months`, `deployment`. Ответ `status`, `questions`, `groups`, источники и сведения для проверки. |
| `GET /catalog/products/{offer_id}` | `X-Demo-Key`. Название, версия, условия и ссылка из выданного каталога. Цена с нулём возвращается как неизвестная. |
| `POST /catalog/quote` | `X-Demo-Key`. `offer_id`, количество выбранных позиций `packages` и `customer`. Формирует черновик КП для проверки менеджером. НДС и сроки остаются на уточнении. |

При тестовой почте передача создаёт уведомление менеджеру, согласование — письмо с PDF счёта и демонстрационным кодом. Допустимые получатели заданы внутри тестового домена `softline-demo.test`. Входящее письмо и готовый текст звонка на этом этапе подаются в API как демонстрационные входы.

Полное ТЗ от 26 ноября ставит подбор по названию и подбор по требованиям на первое место. Для этого сохраняем исходную выгрузку вне Git и строим индекс SQLite. Команда импорта `python -m support_app.catalog путь/к/Mindbox.yml.gz.xml путь/к/catalog.sqlite3`. `SUPPORT_CATALOG_DATABASE` позволяет явно задать путь к готовому индексу. В Docker можно положить его в смонтированную папку `/data` рядом с базой приложения. Индекс включает дату фида, которую API возвращает вместе с вариантами.

Фид организатора — [Mindbox](https://store.softline.ru/feeds/Mindbox.yml.gz). На стенде таймер `sprint48-support-feed-update.timer` обновляет индекс ежедневно в 05:00 МСК. Ручной запуск в контейнере — `python -m support_app.feed_update https://store.softline.ru/feeds/Mindbox.yml.gz /data/catalog.sqlite3`. Скрипт проверяет дату, число позиций с ценами и работу поиска перед заменой индекса. Предыдущий индекс остаётся в `catalog.sqlite3.prev` для команды `python -m support_app.feed_update --rollback /data/catalog.sqlite3`. [Свежесть каталога на стенде](https://analyzebot.ru/support/api/catalog/status).

### Проверка стенда

1. Откройте [чат Softline](https://analyzebot.ru/support/) и напишите «Нужно КП на 19 бессрочных лицензий КриптоПро». Выберите рабочие места и проверьте цену и карточку товара.
2. Откройте [журнал менеджера](https://analyzebot.ru/support/cabinet/#journal) и введите выданный ключ в поле «Ключ менеджера».
3. С ключом жюри выберите учебное обращение, чтобы посмотреть переписку, шаги агента и расход токенов. Во вкладке «Знания» введите общий ответ менеджера, нажмите «Ответить и запомнить», затем задайте вопрос в новом учебном диалоге.
4. [Страница проверки](https://analyzebot.ru/support/api/proof) открывается без ключа: итоги последнего прогона набора и атак (`support_app/proof.json`, обновляется после каждого полного прогона) и живые цифры стенда — обращения, сколько закрыл агент, сколько передал менеджеру, медиана скорости ответа, каталог. Тексты и данные клиентов на ней не показываются.

Скорость в кабинете считается на стенде, а не задана в коде: агент — медиана времени обработки реплики сервером по последним 1 000 ответам, менеджер — медиана от передачи обращения до первого ответа менеджера.

## Безопасность

- Классификация получает разрешённые слова, а ход агента — заранее заданные описания действий и обезличенный итог поиска без цен. Текст и реквизиты обрабатывает сервер. Код проверяет имя инструмента и его параметры.
- Цены и сумма КП рассчитываются по фиду. Скидку свыше 5% и индивидуальные условия оплаты согласует менеджер.
- Каждый ключ жюри открывает отдельную учебную базу, включая сохранение и повторное применение ответа. Изоляцию проверяют тесты `test_cabinet_visibility.py`.
- На конкурсном стенде работает Qwen3.6-35B-A3B с открытыми весами по лицензии Apache 2.0 через API Yandex AI Studio. [Лицензия](https://huggingface.co/Qwen/Qwen3.6-35B-A3B/blob/main/LICENSE) · [Модели Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models).

Офлайн-прогон первых реплик: `python -m support_app.evaluate путь/к/чаты_поддержки.zip путь/к/catalog.sqlite3`. Отчёт содержит только агрегаты. Уточнение, предложение оператора и показ варианта не считаются закрытым обращением. Для оценки закрытия нужны проверенные ответы и сценарии продолжения диалога.

- Агент предлагает демонстрационный купон до 5%. Запрос выше 5% попадает в очередь менеджера с причиной. Если модель недоступна, обработчик продолжает по правилам и может предложить связаться с оператором.

[Тарификация Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing).

- На открытом демо один адрес может создать разговор или отправить реплику до десяти раз за скользящую минуту. Все действия менеджера требуют отдельную авторизацию.

## Как агент решает задачу

Ход агента — цикл «модель ⇄ инструменты» (`support_app/model.py`, `run_agent`), до 4 шагов на реплику:

1. Модель получает обезличенное описание шага и список инструментов: `clarify_requirements`, `search_catalog`, `check_registry`, `draft_quote`, `contact_manager`, `answer_customer`.
2. Читающие инструменты (`search_catalog`, `check_registry`) выполняются сразу. Модель получает их итог — сколько групп вариантов нашлось, какие темы, сколько из них в реестре отечественного ПО — без цен, ссылок и данных клиента (`observe_tool` в `support_app/chat.py`).
3. По итогу модель выбирает следующий шаг: ещё одна проверка, уточнение, черновик КП, передача менеджеру (разрешена, когда в каталоге ничего нет) или ответ клиенту.
4. Действия, которые меняют обращение, выполняет код диалога. Цены, суммы, скидку и реквизиты считает только код.

Каждый шаг пишется в журнал обращения: в кабинете видно «искал в каталоге → проверил реестр → передал КП менеджеру», токены и рубли. Если модель недоступна, исчерпан бюджет или ответ невалиден (лишние параметры, чужой инструмент, повтор), ход идёт по правилам. Тесты цикла — `tests/test_agent_loop.py`.

## Webim и уведомления менеджеру

**Webim «Умный бот 2.0».** Адрес бота в настройках Webim: `https://<стенд>/support/api/webim/<WEBIM_WEBHOOK_SECRET>`. Бот сразу отвечает `{"result": "ok"}`, а ответ клиенту отправляет через API Webim: текст, кнопки, PDF файлом. Когда обращение уходит менеджеру или ход агента сорвался, чат переводится в отдел `WEBIM_DEP_KEY`. Повтор одного события Webim обрабатывается один раз. Переменные: `WEBIM_BASE_URL` (`https://<аккаунт>.webim.ru`), `WEBIM_BOT_TOKEN` (из настроек бота), `WEBIM_WEBHOOK_SECRET` (не короче 24 символов), `WEBIM_DEP_KEY`, `SUPPORT_PUBLIC_URL` (для ссылки на PDF). Проверка — эмулятор API Webim в `tests/test_webim.py`; на живом аккаунте Webim адаптер не проверялся.

**Уведомления менеджеру — Telegram или MAX.** Когда обращение попадает в очередь, менеджер получает сообщение: причина передачи, сумма черновика КП по каталогу и ссылка в кабинет. Имени, почты, телефона, ИНН и текста клиента в сообщении нет — правило одно для обоих каналов, Telegram зарубежный. В кабинете, «Агент → Настройки → Уведомления менеджерам», менеджер включает и выключает уведомления и выбирает канал. Канал без подключённого бота выбрать нельзя. Жюри видит настройку, но не меняет её.

- Telegram: `TELEGRAM_BOT_TOKEN` (@BotFather), `TELEGRAM_CHAT_ID` (из `https://api.telegram.org/bot<токен>/getUpdates` после сообщения в чате).
- MAX: `MAX_BOT_TOKEN` (business.max.ru → Чат-боты → Настройки), `MAX_CHAT_ID`. Запросы идут на `https://platform-api2.max.ru/messages`, токен — в заголовке `Authorization`. Получить `chat_id` группы MAX можно только из события `bot_added`: добавьте бота в чат менеджеров и прочитайте `GET /updates`.
- Общая: `SUPPORT_CABINET_URL` — ссылка в кабинет в тексте уведомления.

Отправка идёт в фоне: сбой мессенджера не задерживает ответ клиенту. Тесты — `tests/test_notify.py`.

## Внедрение в контур Softline

На стенде работают собственный веб-чат и кабинет. Для пилота включаем адаптер Webim на тестовом отделе: переменные выше и адрес бота в настройках Webim. Подключение к рабочему магазину — после приёмки на тестовом отделе. [Документация Webim «Умный Бот 2.0»](https://webim.ru/kb/bots/smart-bot/v-2-0.html)

В пилоте можно использовать тот же порядок ежедневного обновления каталога из фида Mindbox, который уже настроен на стенде.

Модель получает разрешённые слова и описания шагов. Названия компаний, реквизиты и переписка остаются в контуре поддержки. Цены и тексты ответов собирает сервер из каталога и правил.

Предлагаемый пилот — две недели в одной очереди. На первой проверяем подбор, суммы и причины передач на согласованных сценариях. На второй собираем время ответа, долю обращений с подтверждённым результатом, частоту передачи менеджеру и расход модели. Расход и время считаем для одинаковой нагрузки и состава сценариев.

## Развитие после пилота

Простые шаги на том, что уже есть в агенте. Каждый — 1–2 дня работы.

1. **Продление лицензий.** Срок лицензии уже есть в КП. За 30 и 7 дней до его конца агент пишет клиенту в тот же канал и присылает готовое КП на продление по текущим ценам каталога. Клиент продлевает одной кнопкой, Softline получает повторную продажу без обзвона.
2. **Документы для закупки к КП.** Агент уже проверяет реестр отечественного ПО. К КП добавляем номер записи в реестре со ссылкой, класс ПО, срок действия КП и пометку для закупок по 44-ФЗ и 223-ФЗ. Госзаказчик сразу несёт КП в закупку, менеджер не отвечает на письма «пришлите выписку».
3. **Статус обращения и срок ответа.** Клиент спрашивает «что с моим КП?» — агент отвечает из кабинета: у кого обращение и до какого времени будет ответ; ночью честно пишет время начала работы. Если менеджер не взял обращение за 15 минут, уходит второе уведомление в Telegram или MAX.
4. Счёт из учётной системы Softline сразу после подтверждения КП и оплата через ЮKassa в чате.
