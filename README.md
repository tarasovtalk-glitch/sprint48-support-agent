# SMF — ИИ-агент поддержки Softline Store

Конкурсная задача №6 хакатона «ИИКузница». Агент помогает клиентам магазина подобрать лицензии, отвечает на вопросы о заказах и счетах, готовит КП и передаёт сложные обращения оператору со сводкой.

Веб-чат Softline работает на Webim. Интеграция через API «Умный бот 2.0» предусмотрена для пилота. Конкурсное демо использует отдельный стенд и данные, разрешённые организаторами для демонстрации.

Веб-демо — [analyzebot.ru/support/](https://analyzebot.ru/support/). Проект использует индекс официального каталога Softline, выданного организаторами. Исходная выгрузка каталога и обезличенные примеры обращений хранятся отдельно от кода.

## Серверный проход до счёта

Текущая версия использует демонстрационный сценарий Вовы. Цена и дата внутри сценария годятся для проверки арифметики. Счёт помечен как демонстрационный черновик без оплаты.

Python 3.10+, зависимости в `requirements.txt` и шрифт DejaVu Sans или Arial для PDF. Запуск локально через `uvicorn support_app.app:deployment_app --factory --host 127.0.0.1 --port 8767`. Для контейнера используется `Dockerfile`. Папка SQLite должна быть доступна на запись процессу, в контейнере это пользователь `10001`.

`SUPPORT_DATABASE` задаёт путь к SQLite, `SUPPORT_SCENARIO_PATH` — путь к JSON одного сценария с той же структурой, что и `support_app/demo.json`. `SUPPORT_DEMO_KEY` и `SUPPORT_MANAGER_KEY` — отдельные закрытые ключи для тестового стенда, каждый длиной не менее 24 символов. `YANDEX_API_KEY` и `YANDEX_MODEL_URI` включают определение намерения из свободного текста. Действия-кнопки работают и без модели. `SUPPORT_DAILY_BUDGET_RUB` и `SUPPORT_TOTAL_BUDGET_RUB` задают бюджет модели на стенде. `SUPPORT_SMTP_HOST` включает доставку в тестовый Mailpit, порт задаётся `SUPPORT_SMTP_PORT` (1025 по умолчанию). Для повторной доставки включаем в Mailpit `MP_IGNORE_DUPLICATE_IDS`.

## API для фронтенда

Все пути начинаются с `/support/api`. Клиентский токен и ключ менеджера передаём заголовками. В исходники и в сборку фронта их не встраиваем.

Основной режим стенда — `SUPPORT_CHAT_ONLY=1` (по умолчанию). Он принимает только веб-чат, пишет историю и не ставит почтовые задания. Сценарий прежней SMTP-проверки доступен при явном `SUPPORT_CHAT_ONLY=0` и отдельном сценарии. Коммерческое предложение в чате появляется только после решения менеджера. В фиде у позиции КриптоПро `410137` нет артикула, поэтому используется явно подписанный ID предложения. НДС не выдумывается.

Сценарии с известным артикулом обрабатываются по каталогу. При подборе по задаче модель выбирает инструменты уточнения, поиска, проверки реестра и подготовки черновика. Состояние клиента и допустимость действий проверяет сервер. В журнале видны вызовы модели, исполненные инструменты, поиск, проверка реестра, расчёт и передача менеджеру. В модель отправляются только безопасные признаки шага и разрешённые слова. Исходная переписка, название клиента и реквизиты остаются в базе стенда.

| Метод и путь | Вход и результат |
| --- | --- |
| `GET /health` | `204`, если API и база доступны. |
| `POST /sessions` | `X-Demo-Key` для закрытого запуска. На открытом веб-стенде запрос проверяет Caddy, браузер получает `session_token` и `case` без общего ключа. |
| `GET /case` | `Authorization: Bearer <session_token>`. Текущий `state`, `version`, `offer`, `payment_due` и заметка менеджера. |
| `POST /case/messages` | Авторизация клиента. JSON с `text` или серверным `action` и `value` нажатой кнопки. Можно передать `page_url` исходной карточки товара Softline. Ответ `reply`, `intent`, `document_url`, `case`, `messages` и `buttons [{label,action,value}]`. Для веб-чата `channel` отсутствует или равен `chat`. |
| `GET /case/messages` | Авторизация клиента. Восстановление беседы или чтение новых реплик через `?after=<id>`. Ответ `messages [{id,role,text,document_url,buttons,created}]`. |
| `GET /documents/{access_id}` | PDF. Ссылка действует 15 минут, старый счёт перестаёт открываться при смене состояния. |
| `GET /manager/cases` | `X-Manager-Key`. По умолчанию очередь ожидающих. Журнал всех разговоров — `?state=all&limit=50&offset=0`. Каждая строка включает `created`, `updated` в UTC и `first_client_message`, а для КП также `reason` и `quote`. |
| `GET /manager/cases/{id}/messages` | Авторизация менеджера. Переписка обращения с временем каждой реплики. |
| `POST /manager/cases/{id}/decision` | Авторизация менеджера. `choice` (`approve` или `reject`), текущая `version`, UUID `request_id` и необязательный `reply` для клиента. `note` поддерживается как прежнее имя. Повтор той же команды возвращает её результат. Устаревшая версия даёт `409`. При подтверждении КП `document_url` также появляется в истории клиента. |
| `POST /manager/cases/{id}/rule` | Авторизация менеджера, `confirmed: true`. После ручного согласования создаёт правило по этому клиенту и договору. |
| `GET /manager/cases/{id}/journal` | Авторизация менеджера. События и токены модели для калькулятора. |
| `GET /manager/knowledge` | Авторизация менеджера. Сохранённые правила с основанием и источником. |
| `POST /catalog/selection` | `X-Demo-Key`. JSON `mode` (`known` или `needs`), `query`, `product` для известного продукта и уточнения `users`, `term_months`, `deployment`. Ответ `status`, `questions`, `groups`, источники и сведения для проверки. |
| `GET /catalog/products/{offer_id}` | `X-Demo-Key`. Название, версия, условия и ссылка из выданного каталога. Цена с нулём возвращается как неизвестная. |
| `POST /catalog/quote` | `X-Demo-Key`. `offer_id`, количество выбранных позиций `packages` и `customer`. Формирует черновик КП для проверки менеджером. НДС и сроки остаются на уточнении. |

При тестовой почте передача создаёт уведомление менеджеру, согласование — письмо с PDF счёта и демонстрационным кодом. Допустимые получатели заданы внутри тестового домена `softline-demo.test`. Входящее письмо и готовый текст звонка на этом этапе подаются в API как демонстрационные входы.

Полное ТЗ от 26 ноября ставит подбор по названию и подбор по требованиям на первое место. Для этого сохраняем исходную выгрузку вне Git и строим индекс SQLite. Команда импорта `python -m support_app.catalog путь/к/Mindbox.yml.gz.xml путь/к/catalog.sqlite3`. `SUPPORT_CATALOG_DATABASE` позволяет явно задать путь к готовому индексу. В Docker можно положить его в смонтированную папку `/data` рядом с базой приложения. Индекс включает дату фида, которую API возвращает вместе с вариантами.

Офлайн-прогон первых реплик: `python -m support_app.evaluate путь/к/чаты_поддержки.zip путь/к/catalog.sqlite3`. Отчёт содержит только агрегаты. Уточнение, предложение оператора и показ варианта не считаются закрытым обращением. Для оценки закрытия нужны проверенные ответы и сценарии продолжения диалога.

## Проверки демо

- Стоимость позиции берётся из индекса. Сервер умножает цену на количество и повторно читает карточку перед отправкой КП на проверку.
- Агент предлагает демонстрационный купон до 5%. Запрос выше 5% попадает в очередь менеджера с причиной. Если модель недоступна, обработчик продолжает по правилам и может предложить связаться с оператором.
- При замере на VPS подбор защиты для 50 рабочих мест до отправки КП использовал 5 вызовов Alice AI LLM Flash, 659 входящих и 46 выходящих токенов. Стоимость — 0,0751 ₽ с НДС. Измеренные ответы с моделью занимали от 0,54 до 1,78 с без учёта браузера и действий пользователя.
- В офлайн-прогоне 495 первых реплик было 49 ответов с вариантами из каталога и 34 передачи менеджеру. Для доли закрытых нужны проверки результата по каждому диалогу.
- На открытом демо один адрес может создать разговор или отправить реплику до десяти раз за скользящую минуту. Все действия менеджера требуют отдельную авторизацию.
